Production deployment

A checklist for taking DripStack from the local demo to a real environment.

1 · Managed infrastructure

  • Postgres 16 (RDS / Cloud SQL / Neon).
  • RabbitMQ (CloudAMQP or self-hosted).
  • Temporal — Temporal Cloud or a self-hosted cluster (the local start-dev server is not for production).

Point DATABASE_URL, RABBITMQ_URL, and TEMPORAL_ADDRESS/TEMPORAL_NAMESPACE at them.

2 · Secrets & environment

NODE_ENV=production
APP_BASE_URL=https://app.yourdomain.com
DASHBOARD_URL=https://console.yourdomain.com
JWT_ACCESS_SECRET=$(openssl rand -hex 32)
JWT_REFRESH_SECRET=$(openssl rand -hex 32)
LINK_SIGNING_SECRET=$(openssl rand -hex 32)
The API and worker will refuse to start in production with default or weak secrets. This is intentional.

3 · Migrate & seed

cd backend
uv sync                      # add --extra ses for AWS SES
uv run alembic upgrade head
uv run seed                  # once, to create the platform org + roles

4 · Run the processes

API and worker are independent and scale separately.

# API (run behind a TLS-terminating proxy / load balancer)
uv run api

# Worker(s) — scale horizontally for throughput
uv run worker

For more control, run uvicorn with multiple workers, e.g. uvicorn dripstack.api.main:app --host 0.0.0.0 --port 4000 --workers 4.

5 · Health checks

ProbeEndpointBehaviour
LivenessGET /healthAlways 200 if the process is up.
ReadinessGET /ready200 when the database is reachable; 503 otherwise — hold traffic until ready.

6 · Dashboard

pnpm --filter @dripstack/dashboard build
pnpm --filter @dripstack/dashboard start   # Next.js production server

Set NEXT_PUBLIC_API_URL to your API's public URL at build time.

7 · Operational notes

  • Logs are structured JSON (structlog) — ship to your log platform.
  • Outbound webhook retries use a dead-letter exchange; monitor the outbound queue depth in RabbitMQ.
  • Inspect workflows and durable timers in the Temporal Web UI.
  • Rotate signing secrets periodically; review the audit log for anomalies.
  • Back up Postgres; it holds all runs, message logs, and the audit trail.

Containerization

The backend is a standard uv project: a production image installs uv, runs uv sync --no-dev, and uses uv run api or uv run worker as the entrypoint. Run database migrations as a one-shot job before rolling out a new release.
