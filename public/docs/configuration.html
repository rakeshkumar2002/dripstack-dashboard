Configuration

Everything is driven by environment variables, validated centrally in backend/src/dripstack/config.py.

Copy .env.example → .env. The repo-root .env is located by walking up from the current directory, so the API, worker, seed, and Alembic all read the same file regardless of where they're launched.

Secrets

Production guard: when NODE_ENV=production, the API and worker refuse to start if any secret below is still its dev default or shorter than 32 characters. Generate strong values with openssl rand -hex 32.
VariablePurpose
JWT_ACCESS_SECRETSigns short-lived access tokens.
JWT_REFRESH_SECRETSigns refresh tokens.
LINK_SIGNING_SECRETHMAC key for tracked-link tokens.
JWT_ACCESS_TTL / JWT_REFRESH_TTLToken lifetimes (e.g. 15m, 7d).

Google sign-in

Platform-level, unlike the per-organization OIDC connection below: one Google OAuth app for the whole deployment, so there is no organization to choose at the login screen. Unset these and the login page hides the button.

VariablePurpose
GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRETFrom an OAuth 2.0 Client ID (type: Web application) in the Google Cloud console.
GOOGLE_ISSUERDefaults to https://accounts.google.com; override only to point at a compatible test issuer.

Register the redirect URI APP_BASE_URL + /api/v1/auth/google/callback on the OAuth client — Google matches it exactly, including scheme and port. A verified Google email is resolved to its DripStack user by User.email, which is globally unique; an email with no user is rejected, never provisioned.

SSO is configured per organization at runtime, not via env — see Integrations → SSO.
