Security model

Defense in depth across ingestion, links, auth, tenancy, and transport.

Tracked links

  • Signed & tamper-proof. Every action/log/pixel/redirect link carries an HMAC token over (run_id, scope, ref) using LINK_SIGNING_SECRET.
  • Actions require POST. A GET on an action link renders a confirmation interstitial; the state change only happens on the POST the user submits. This stops email/AV link-scanners and client prefetch — which issue GETs — from silently resolving or escalating incidents.
  • No open redirect. Redirect links bind the destination URL into the signature and require an http(s) scheme, so u= can't be swapped for a phishing target.

Inbound webhooks

  • HMAC-verified against the raw request bytes (read before JSON parsing), constant-time compared. Supports a bare hex digest or a sha256= prefix.
  • Rate-limited (ingest 120/min; global 1000/min).
  • Idempotent — duplicate payloads within 5 minutes are de-duped by hash.

Authentication & authorization

  • Passwords are bcrypt-hashed. SSO-provisioned users get an unusable hash so they can't password-login.
  • Tokens — short-lived access JWTs + refresh tokens (HS256).
  • RBAC — every endpoint is gated by a permission key (users.write, integrations.write, …). Three system roles: integration-admin (platform), customer-admin, customer-member.
  • Tenant isolation — every table carries organization_id; for_org() injects the scope into every query, so a handler physically cannot read or write across organizations. Proven by test_tenant.py.
  • Last-admin protection — you cannot demote/disable/delete the org's last active admin, or your own admin access.

Audit log

An append-only AuditLog records security-relevant actions — logins (success and failure), SSO logins, user create/update/delete, SSO configuration — with actor, target, hashed client IP, and metadata. Read via GET /api/v1/audit-logs (requires users.read).

Secrets handling

  • Channel webhook URLs and SSO client secrets live in dedicated tables, never in Organization.settings (which is serialized to clients). APIs return masked views only.
  • Production secret guard: with NODE_ENV=production, the API and worker refuse to boot if JWT_ACCESS_SECRET, JWT_REFRESH_SECRET, or LINK_SIGNING_SECRET are still defaults or shorter than 32 characters.

Transport & headers

  • CORS is locked to DASHBOARD_URL.
  • Every response carries X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy, Cross-Origin-Opener-Policy, and Permissions-Policy; HSTS is added in production.
  • Outbound webhooks are signed with x-dripstack-signature.

Reporting

For a real deployment, route security reports to a monitored inbox and rotate JWT_* / LINK_SIGNING_SECRET on a schedule.
